# Adler & Öktem — Learned Primal-Dual Reconstruction (IEEE TMI 2018)

- **Authors**: Jonas Adler, Ozan Öktem (KTH Royal Institute of Technology / Elekta AB)
- **arXiv**: [1707.06474](https://arxiv.org/abs/1707.06474) (v3, 5 Jul 2018)
- **Published**: IEEE Transactions on Medical Imaging, 2018
- **PDF**: `papers/1707.06474_Adler_LearnedPrimalDual_TMI2018.pdf`
- **Code (original)**: https://github.com/adler-j/learned_primal_dual

## TL;DR

The canonical "trainable unrolled iterative reconstruction" paper for
tomography. Unrolls a primal-dual hybrid gradient (PDHG /
Chambolle-Pock) iteration into a deep network where the **proximal
operators are replaced by small CNNs** that are learned end-to-end.
The forward operator (ray transform) and its adjoint (back-projection)
are kept as differentiable layers inside the network, so the network
learns the *update rule* for an iterative solver, not the whole
reconstruction. With only 10 unrolled iterations and ~2.4 × 10⁵
parameters, it beats FBP, TV, FBP+U-Net post-processing, and previous
learned schemes by 6.6 dB PSNR on human-phantom low-dose CT.

This is the paper you cite when you want to do "trainable ADMM-style"
CT reconstruction — Adler shows it generalises classical PDHG /
ADMM / gradient-descent / learned-gradient schemes as special cases
(§III-D).

## What problem it solves

Inverse problem: recover `f_true ∈ X` from data `g = T(f_true) + δg`
where `T: X → Y` is the (possibly non-linear) forward operator and
δg is noise. Variational reconstruction minimises

    f̂ = argmin_f { L(T(f), g) + λ S(f) }

with `S` a hand-designed regulariser (TV, dictionary, wavelets, …).
Adler & Öktem replace this hand-designed pipeline with one that
**learns the update rule** while keeping `T` and `T*` baked in as
known operators.

## Algorithm

### Classical PDHG (Chambolle-Pock 2010, Algorithm 1)

For `min_f { F(K(f)) + G(f) }`:

```
for i = 1, …:
    h_{i+1} ← prox_{σF*}( h_i + σ K(f̄_i) )
    f_{i+1} ← prox_{τG} ( f_i − τ [∂K(f_i)]*(h_{i+1}) )
    f̄_{i+1} ← f_{i+1} + γ (f_{i+1} − f_i)
```

### Learned PDHG (Algorithm 2): replace prox with CNNs

```
for i = 1, …, I:
    h_{i+1} ← Γ_{θ_i^d}( h_i + σ K(f̄_i), g )       # dual proximal → CNN
    f_{i+1} ← Λ_{θ_i^p}( f_i − τ [∂K(f_i)]*(h_{i+1}) )  # primal proximal → CNN
    f̄_{i+1} ← f_{i+1} + θ (f_{i+1} − f_i)
```

The CNN proximals `Γ_θ^d` and `Λ_θ^p` are tiny 3-layer residual
blocks; the forward `K` (here just the ray transform `T = P`) and its
adjoint `[∂K]* = P*` (back-projection) remain hard-coded.

### Learned Primal-Dual (Algorithm 3): the actual contribution

Three changes on top of Learned PDHG that take it from "comparable
to traditional methods" → "+6 dB PSNR over FBP+U-Net post-processing":

1. **Memory between iterations** — extend the primal space to
   `X^{N_primal}` and the dual space to `U^{N_dual}` so each iterate
   carries multiple channels. The CNN can attend to "old" iterates,
   not just the most recent.
2. **Let the network learn how to combine the previous iterate with
   the result of the operator evaluation.** Drop the hard-coded
   `h_i + σ K(f̄_i)` form — feed both into the CNN and let it figure
   out the linear combination.
3. **Drop the over-relaxation step** `f̄ = f + θ(f − f_prev)` — let
   the network choose what point the forward operator is evaluated
   at.
4. **Iteration-specific proximals** (no parameter sharing across
   iterations) — increases parameter count but improves quality
   meaningfully.

```
Initialize f_0 ∈ X^{N_primal} = 0,  h_0 ∈ U^{N_dual} = 0
for i = 1, …, I:
    h_i ← Γ_{θ_i^d}( h_{i-1}, K(f_{i-1}^{(2)}), g )
    f_i ← Λ_{θ_i^p}( f_{i-1}, [∂K(f_{i-1}^{(1)})]*(h_i^{(1)}) )
return f_I^{(1)}
```

The proximal CNNs are **3-layer residual blocks** of the form
`Id + W_3 ∘ PReLU ∘ W_2 ∘ PReLU ∘ W_1` where each `W_j` is a `3 × 3`
convolution with a small bias term (32 channels in the hidden layers,
`N_primal = N_dual = 5` channels in the primal/dual state). Total
network: 60 conv layers, ~2.4 × 10⁵ parameters, 10 unrolled iterations.

## Connection to other unrolled schemes (§III-D)

Learned Primal-Dual subsumes:
- **Classical PDHG** — set `N_primal=2`, `N_dual=1`, fix the
  combining ops to the hard-coded forms above.
- **Gradient descent** with step-length α — choose
  `Λ(f, x) = f − α ([∇G](f) + [∂K(f)]*([∇F](K(f))))` and a similar
  dual update.
- **Learned ADMM-Net** (Sun, Li, Xu 2016) — special case of the
  Learned PDHG variant where the prox CNNs are constrained to
  ADMM-style updates.
- **Learned-gradient schemes** (Adler-Öktem 2017 *Inverse Problems*)
  — the precursor where the forward operator's *gradient* (not the
  operator itself) is the only physics-aware piece.

This is the framework around which most "trainable iterative CT
reconstruction" papers are built. ITNet (used in this repo's
`solver_itnet_v3.py`), Hammernik VN, Schlemper DC-CNN, primal-dual
networks for MRI, etc. all fall in this family.

## Training & implementation details

| Item | Value |
|---|---|
| Library | TensorFlow + ODL (Operator Discretization Library) + astra_gpu (forward / back-projector) |
| Iterations | `I = 10` |
| Primal / dual channels | `N_primal = N_dual = 5` |
| Per-iter CNN | 3 × 3 conv, channels 6→32→32→5 (primal), 7→32→32→5 (dual) |
| Total params | ≈ 2.4 × 10⁵ (60 conv layers) |
| Optimizer | Adam, β₂ = 0.99 |
| LR schedule | Cosine annealing, η₀ = 10⁻³, 10⁵ batches |
| Batch size | 5 (ellipse phantoms) / 1 (human phantoms) |
| Loss | Mean-squared error (Eq. 5) |
| Regularisation | **None** (no weight decay, no dropout, no batchnorm, no augmentation) |
| Gradient clipping | Global norm ≤ 1 |
| Init | Xavier; biases 0 |
| Training hardware | Single GTX 1080 Ti |
| Training time | 11 h (ellipses) / 40 h (human phantoms) |
| Test geometry | Fan-beam, 1000 angles × 1000 detector pixels, 512 × 512 reconstruction |
| Noise model | Beer-Lambert with Poisson noise, I₀ = 10⁴ |

## Results

### Ellipse phantoms (Shepp-Logan val, 30 views, 5 % Gaussian noise, 128 × 128)

| Method | PSNR | SSIM | Runtime (ms) | Params |
|---|---:|---:|---:|---:|
| FBP | 19.75 | 0.597 | 4 | 1 |
| TV (1000 PDHG iters) | 28.06 | 0.929 | 5166 | 1 |
| FBP + U-Net denoising | 29.20 | 0.944 | 9 | 10⁷ |
| FBP + residual denoising | 32.38 | 0.972 | 9 | 1.2 × 10⁵ |
| Learned gradient | 32.29 | 0.981 | 56 | 1.2 × 10⁴ |
| Learned PDHG | 28.32 | 0.909 | 48 | 2.4 × 10⁴ |
| Learned Primal | 36.97 | 0.986 | 43 | 1.2 × 10⁵ |
| **Learned Primal-Dual** | **38.28** | **0.989** | 49 | 2.4 × 10⁵ |

### Human phantoms (Mayo AAPM LDCT challenge, 9 patients train / 1 val, 512 × 512)

| Method | PSNR | SSIM | Runtime (ms) | Params |
|---|---:|---:|---:|---:|
| FBP | 33.65 | 0.830 | 423 | 1 |
| TV | 37.48 | 0.946 | 64371 | 1 |
| FBP + U-Net denoising | 41.92 | 0.941 | 463 | 10⁷ |
| **Learned Primal-Dual (linear)** | **44.11** | **0.969** | 620 | 2.4 × 10⁵ |
| Learned Primal-Dual (non-linear) | 43.91 | 0.969 | 670 | 2.4 × 10⁵ |

Compared to FBP+U-Net post-processing (a strong baseline on human
data), Learned Primal-Dual gains **+2.2 dB PSNR** with **40× fewer
parameters** (2.4 × 10⁵ vs 10⁷) at comparable runtime.

## What the iterates look like

Figure 5 (page 10) visualises iterates 2, 4, 6, 8, 10:

- Iterates 1-7 stay "very bad" visually — large-scale structure
  forming.
- Iterates 8-10 perform an **edge-enhancing step**: the texture
  sharpens dramatically.
- In the dual (sinogram) space the back-projected residual is
  effectively **band-pass filtered** to exclude very low and very
  high frequencies.

Practical takeaway: the network learns a coarse-to-fine
reconstruction strategy automatically, even though the loss is just
pointwise MSE.

## Failure modes & honest limitations (from the paper's Discussion)

1. **Slight over-smoothing.** Despite winning PSNR/SSIM, the
   reconstructions visually appear smoother than ground truth. The
   authors attribute this to **using squared-norm loss** (Eq. 4) and
   suggest perceptual losses (Johnson et al. 2016) as a remedy.
2. **Non-linear forward model didn't help.** The non-linear
   Beer-Lambert variant gave essentially identical PSNR/SSIM to the
   linear pre-log variant; the authors recommend working on **post-log
   data** for simplicity.
3. **Sensitive to optimizer / LR schedule.** The authors observed
   "large impact on the results" from these choices — Adam β₂=0.99
   and cosine annealing were not arbitrary.
4. **Slower than post-processing** for non-tomographic settings. On
   small (ellipse) data, ~6× slower than FBP+U-Net. On large (human
   phantom) data, comparable — because FBP itself dominates the
   post-processing time anyway.

## Why this matters for Agent4CT

### As a reference solver to add

There's currently **no Learned Primal-Dual variant in the repo**.
Adding one would fill a gap between:

- `solver_itnet_v2.py` / `solver_itnet_v3.py` — ITNet (also unrolled
  primal-dual-flavoured, but different parametrisation)
- `solver_hammernik_2017.py` / `solver_hammernik_vn.py` —
  Hammernik VN (unrolled gradient descent + variational regulariser)
- `solver_dual_ddomain_*.py` — Wagner dual-domain (one shot, no
  unrolling)

A clean Learned Primal-Dual port would let us probe whether **explicit
primal-dual unrolling** vs ITNet's parametrisation vs
Hammernik's gradient-descent unrolling matters on the Pentathlon
challenges.

### Sketch for `solver_learned_primal_dual.py`

```python
class LearnedPrimalDual(nn.Module):
    def __init__(self, geom, I=10, n_primal=5, n_dual=5, c_hidden=32):
        self.geom = geom
        self.R = PyronnFanBeamProjector(geom)  # T and T* via autograd
        self.dual_blocks  = nn.ModuleList([
            ResBlock3(in_c=n_dual + 2, hid_c=c_hidden, out_c=n_dual)
            for _ in range(I)
        ])
        self.primal_blocks = nn.ModuleList([
            ResBlock3(in_c=n_primal + 1, hid_c=c_hidden, out_c=n_primal)
            for _ in range(I)
        ])
        # 2.4e5 params at the defaults above.

    def forward(self, g):  # g: sinogram (B, 1, A, D)
        B = g.shape[0]
        f = torch.zeros(B, self.n_primal, H, W, device=g.device)
        h = torch.zeros(B, self.n_dual, A, D, device=g.device)
        for i in range(self.I):
            Kf2 = self.R.forward_project(f[:, 1:2])  # K(f^(2))
            h   = self.dual_blocks[i](torch.cat([h, Kf2, g], dim=1))
            Adjh = self.R.back_project(h[:, 0:1])     # T*(h^(1))
            f   = self.primal_blocks[i](torch.cat([f, Adjh], dim=1))
        return f[:, 0:1]  # primary primal channel
```

Train with `supervised_recon_loss(pred, truth, lambda_neg=1.0,
base="mse")` (consistent with the supervised-L2 finding for
breast-CT, see `docs/findings.md` 2026-05-22) and **iteration-specific
proximals** (no weight sharing) per Adler's recommendation.

### Hints for the autoresearch agent that picks this up

- **Channels (`N_primal = N_dual`)**: Adler uses 5. Worth sweeping
  {3, 5, 7, 10} — more channels = more iter-memory.
- **Iterations `I`**: 10 in the paper. The cost is linear in I and
  doubles with `I = 20`. Try {5, 10, 15} on breast-CT.
- **CNN block depth**: 3-layer residual block. Deeper blocks per iter
  could substitute for more iterations.
- **No regularisation worked for Adler.** Don't waste iters on
  weight decay / dropout / batch norm. He explicitly tried *none of
  them*.
- **MSE loss has a known over-smoothing failure mode** on human
  phantoms (visible in Adler's Fig. 4). On breast-CT this may
  matter for fibroglandular detail. **Try perceptual / L1 loss**
  early.
- **Initialise from zero** primal and dual states. Adler tested
  initialising from FBP and reports it gave only "marginal" training
  speedup with no final-quality difference.
- **Apply to the post-log forward model.** Pre-log non-linear
  Beer-Lambert offered no measurable benefit in Adler's experiments.
